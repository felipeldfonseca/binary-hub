## 0. Decisions at a glance

1. **Exits live in a new append-only table `trade_exits`**, one row per exit, never per entry (decision 1: exits-only).
   A trade has rows there only when it has more than one exit (a partial in the app, or a broker position in several
   rows). **Every trade that exists today, and every future trade without a partial, keeps its single exit in `trades`
   exactly as now** and has no row in `trade_exits`. No backfill; no column added to `trades`.
2. **Two origins, one rule for what counts.** `origin = 'app'` rows are what the trader registered (frozen forever, with
   the server's `registered_at`); `origin = 'file'` rows are a broker file's, kept per import batch. A trade's exits
   that count (`trade_exits_v.counts`) are its file rows when it has any (the file wins on money, Phase 3 decision 2),
   else its app rows not undone. Undoing a batch deletes its file rows, so the app's rows count again: undo is exact.
3. **`trades` holds the sums.** On a closed trade with exits: `quantity` = Σ exit quantities (= the position),
   `exit_time` = the last exit, `exit_price` = the quantity-weighted average (8 decimals), `pnl` = Σ gross pnl,
   `commission` = Σ (null when none is known), `result` = sign of `pnl`, `pnl_basis` = `file` > `typed` > `estimate` >
   `prices`. An open trade with partials keeps Phase 3's open shape (no exit, no pnl, `result = 'pending'`); its realized
   money is in `trade_exits` only. A **deferred constraint trigger** checks at commit, for every trade an exit or a sum
   column touched, that the sums hold (`exits_mismatch`, a bug code, never seen by a correct writer) — proven.
4. **R is measured on the initial stop**: `trades.stop_price` is already frozen at entry by `trades_guard`; stop moves
   never write it. R = Σ qᵢ·(pᵢ − entry)·side ÷ (Q·|entry − initial stop|) = (average exit − entry)·side ÷ risk distance.
   No initial stop → no R (a later stop move does not create one).
5. **The daily limit counts each exit at its own instant** (`limit_usage` replaced): a trade without counting exits is
   one row at `coalesce(exit_time, entry_time)` exactly as before; a trade with exits is one row per exit at its
   `exit_time`, **an open trade's partials included**. Same trading day rule (the trade's entry day). Proven identical on
   every stored day, scope, limit and instant (§6).
6. **Partial hours**: typed «HH:MM» on the account's clock like «Hora da saída» as built (absent = now; not in the
   future; not before the entry), `registered_at` always the server's. Recommended: **no 15-minute cap** (the cap is
   the entry's rule because the gate judges the entry; an exit has none as built, and a partial is an exit). The cap is a
   one-line alternative if the owner wants it (§8.2, Q1).
7. **Stop moves live in a new append-only table `trade_stop_moves`** (server time only, no typed hour): kind
   `breakeven` (the «Breakeven» shortcut: the stop at the entry price as it was then) or `ajuste` (any level: stop
   móvel), the new level, the level before, **the points in favour at that moment as typed** (required for a breakeven;
   in the instrument's unit of stops: points, pips or price), and the breakeven rule of the trade's version copied for
   reading. Only on an open live app trade. «Já fechada» may tell one breakeven (`origin = 'reconstructed'`, never «ao
   vivo»). A view flags «ao vivo» with the marks' «limpa» rule.
8. **The breakeven rule is per account and versioned**: `AccountRules.breakeven = null | {"favor": N}`; the resolved
   version gets a **tenth key `"breakeven"` only when the rule is set**. Every account without it resolves to exactly
   the jsonb it resolves to today, so **no account gets a version nobody chose** (the trap of jsonb equality in
   `save_rules`, `20261019000001:769`). Setting it creates one version for that account only; turning it off, another.
   Never on binaries (`not_for_market`). The app suggests it, never blocks; Análises (Phase 6) check it from stored facts.
9. **Undo**: «Desfazer entrada» stays as built (open, live, within 15 minutes of the entry's registration) and now takes
   the trade's partials and stop moves with it (cascade; `trade_deletions` logs it as before). **«Desfazer parcial»
   (N)**: the last partial of an open live trade, within 15 minutes of its own registration, is marked undone
   (`voided_at`, set once), kept, never counted. Stop moves have no undo: a wrong move is corrected by another move (the
   history shows both). An exit stays without undo (as built).
10. **Ebinex/binaries excluded everywhere**: no partial, no stop move, no breakeven rule, no grouping in files (guards
    and validators refuse with `not_for_market`).
11. **Imports**: rows of one broker position (price market; same symbol, side, open instant and open price; with an
    exit) are **one trade with one file exit per row** (Top One writes one row per exit; its `SL` is always empty). A
    one-row position behaves exactly as Phase 3 (same statements, same answers, same batch counts). A position linked to
    an app trade keeps the app's registered hours (same number of exits: the app's hours in order; otherwise the file's,
    inside the trade, with the app's final exit hour last); an open app trade is closed by the file at its last exit
    (never after now). A later file that brings more exits of a position already in the account **attaches** them to
    that trade. Re-importing never regroups trades that already exist: **the owner's existing pair stays two trades**.
12. **Fixes a pre-existing bug** in `import_undo` (`20261020000004:595-603`): the «give back» patch also rewrote an
    *earlier* batch's `before` when its value happened to equal the undone batch's `after`; undone newest first, the
    registered value was lost. Reproduced on the as-built functions (registered pnl 100.00 → 80.00) and fixed by limiting
    the patch to later batches (`x.linked_at > l.linked_at`) (§9.8).
13. **Old pages** read the sums (average exit price, total pnl, total size, last exit), so a trade with partials looks
    like one trade there. While open they see `pending` (as built), so a realized partial reaches them only at the
    close. Deleting from `/trades` cascades. No change to their code.
14. **Rollout**: two migrations, one paste kit (backup schema, one transaction, a conferência that proves no stored row,
    no rule resolution, no `limit_usage`/«Posso operar hoje?» answer changed, then the JSON for the owner), and an undo
    kit that refuses once any partial, stop move or breakeven rule exists.

## 3. Schema

### 3.1 `trade_exits` (NEW, append-only)

```sql
create table public.trade_exits (
  id bigint generated always as identity primary key,
  user_id uuid not null references auth.users (id) on delete cascade,
  trade_id uuid not null,
  account_id uuid not null,                       -- the trade's (the guard copies it): the key of a file ticket
  origin text not null check (origin in ('app', 'file')),
  kind text,                                      -- app: 'parcial' (left the trade open) | 'final' (closed it); file: null
  quantity numeric(18, 8) not null check (quantity > 0),
  exit_price numeric(18, 8) check (exit_price is null or exit_price >= 0),   -- an option may end at 0
  exit_time timestamptz not null,                 -- when it was realized (typed, or the file's / the app's paired hour)
  registered_at timestamptz not null default now(),   -- server, forced by the guard
  pnl numeric(18, 2) not null,                    -- gross, account currency
  pnl_basis text not null check (pnl_basis in ('prices', 'estimate', 'typed', 'file')),
  commission numeric(18, 2) check (commission is null or commission >= 0),   -- null = unknown
  voided_at timestamptz,                          -- «Desfazer parcial» (app 'parcial' only), set once
  batch_id uuid, line int, source_platform text, external_id text,          -- file rows only
  file_exit_at timestamptz,                       -- the file's own instant (exit_time may be the app's)
  source_local_exit timestamp,                    -- the file's wall clock (imported trades: import_fix_tz)
  check ((origin = 'app') = (kind is not null)),
  check ((origin = 'file') = (batch_id is not null)),
  check (origin = 'app' or (line, source_platform, external_id, file_exit_at) are all not null),
  check (origin = 'file' or (line, source_platform, external_id, file_exit_at, source_local_exit) are all null),
  check (voided_at is null or kind = 'parcial'),
  foreign key (trade_id, user_id) references public.trades (id, user_id) on delete cascade,
  foreign key (account_id, user_id) references public.trading_accounts (id, user_id),
  foreign key (batch_id, user_id) references public.import_batches (id, user_id)
);
create index trade_exits_trade on public.trade_exits (trade_id, exit_time, id);
create index trade_exits_batch on public.trade_exits (batch_id) where batch_id is not null;
create unique index trade_exits_ticket on public.trade_exits (account_id, source_platform, external_id) where origin = 'file';
```

Why a table and not columns: an exit is an event with its own time (the limit needs it), money (the file corrects it)
and provenance (undo must remove exactly one batch's rows). Why rows only for multi-exit trades: no backfill of 631
rows, no duplicated truth for single-exit trades, and the as-built code paths stay byte-identical for them (proven by
the repo suites). Why both origins in one table: one view decides what counts; the app's registration is never
overwritten (append-only), the file's version comes and goes with its batch.

Ticket keys: a grouped imported trade carries its first exit's ticket in `trades.external_id` (as the old notes key
`topone:<ticket>`); every exit's ticket is in `trade_exits.external_id`. Duplicate detection and «ID in another account»
look at both (§9.2).

### 3.2 `trade_stop_moves` (NEW, append-only)

```sql
create table public.trade_stop_moves (
  id bigint generated always as identity primary key,
  user_id uuid not null references auth.users (id) on delete cascade,
  trade_id uuid not null,
  origin text not null check (origin in ('live', 'reconstructed')),
  kind text not null check (kind in ('breakeven', 'ajuste')),
  stop_price numeric(18, 8) not null check (stop_price > 0),   -- the new level
  prev_stop numeric(18, 8),                                    -- the level before (initial stop or last move); null = none
  favor numeric(18, 8),                                        -- points in favour then, as typed, signed
  unit text not null check (unit in ('pts', 'pips', 'price')), -- the instrument's unit of stops at the move
  rule_favor numeric(18, 8),                                   -- the trade version's «+N», copied for reading; null = no rule
  moved_at timestamptz not null default now(),                 -- server, forced by the guard
  check (kind = 'ajuste' or favor is not null),
  foreign key (trade_id, user_id) references public.trades (id, user_id) on delete cascade
);
create index trade_stop_moves_trade on public.trade_stop_moves (trade_id, moved_at, id);
```

`kind` is stored, not derived: the file may later correct `entry_price` (decision 2), and a stop the trader put «no
breakeven» at 7.912,50 stays a breakeven move even if the file says the fill was 7.912,75. `favor` is kept as typed in
its unit (what the trader saw); price distance = `favor × pip` for `pips`, `favor` otherwise.

### 3.3 Views (NEW, `security_invoker`)

- `trade_exits_v`: every `trade_exits` column the app needs plus `counts` = `origin = 'file'` or (`voided_at is null`
  and the trade has no file row). (Optional for Phase 6: `ao_vivo` = app row, live context, `registered_at ≤
  coalesce(exit_registered_at, registered_at)`.)
- `trade_stop_moves_v`: every column plus `ao_vivo` = `origin = 'live'` and `moved_at < least(result_known_at,
  exit_registered_at)` (the marks' rule: a move registered after a file says the trade had already ended is not «ao
  vivo»).

### 3.4 What does not change

No column is added to `trades`, `trade_import_links`, `import_batches`, `trade_entry_context` or any rules table.
`trade_import_links.before/after` may now carry the key `source_local_exit` (an imported trade's last exit moved by an
attach), which `import_col_equal` learns to compare. `trade_caps_all()`/`instrument_specs()` are untouched (no
descriptor parity change in the app).

## 4. Trades and their exits

### 4.1 The sums (`trade_exits_sum(trade)`, `trade_exits_apply(trade)`, internal)

`trade_exits_sum` returns, over the counting exits: `n`, `quantity`, `pnl`, `commission` (null if none known),
`exit_price` = `round(Σ q·p ÷ Σ q, 8)` (null if any price is null), `last_at`, `basis`. `trade_exits_apply` writes them
on a **closed** trade (an open one keeps no exit and no result). Every writer of exits calls it or writes the same
values. `exit_time` is included: on a trade whose exit the app registered it must equal the frozen value — `trades_guard`
turns any drift into `frozen`, so the guard doubles as an assertion.

Rounding: the average has 8 decimals (the column's scale; it may be off the tick, it is an average). The pnl is never
recomputed from the average: it is the sum of the exits' own (cent-rounded) pnl, as the broker reports per row.
Example (proven): long 3 MES @ 7.912,50; partial 1 @ 7.916,50 (+US$ 20); rest 2 @ 7.920,50 (+US$ 80) → `pnl` 100.00,
`exit_price` 7919.16666667, R (stop 10 pts) = (1×4 + 2×8) ÷ (3×10) = 0.6667.

### 4.2 The invariant (deferred constraint triggers `trade_exits_sums`, `trades_exits_sums`; SECURITY DEFINER)

At commit, for each trade touched (an exit inserted/updated/deleted, or a `trades` update of `quantity, exit_price,
exit_time, pnl, commission, result, status`): if the trade has counting exits then
- no counting exit before `entry_time`;
- **open**: Σ counting quantity < `quantity` (a partial leaves something open);
- **closed**: `(quantity, exit_time, pnl, exit_price, commission)` = the sums and `result` = sign(`pnl`); and, when the
  counting exits are the app's, one of them is `kind = 'final'`.
Else `exits_mismatch` (hint `exit_time` | `quantity` | `sums` | `final`). A trade that is gone (cascade) or has no
exits is skipped. Proven: a superuser `update trades set pnl = 99` on such a trade fails at commit.

### 4.3 `pnl_basis`

Single-exit trades: unchanged. With exits: `file` if any counting exit is a file row (then all are), else `typed` if
any is typed (or corrected with «Corrigir»), else `estimate` if any is an estimate (dollar-base forex), else `prices`.

### 4.4 R

Not stored (as built: returned by `register_exit`/`register_after` and now in `trade_state.position.r`).
`trade_r_of(entry, initial_stop, side, Q, exits)`; for a single exit it reduces exactly to the as-built
`round(points ÷ |entry − stop|, 4)`. The file may change `entry_price` and the exits (money): R follows (derived), the
initial stop does not move.

### 4.5 Which markets

Every price market of `trade_caps_all()` (futures, forex, stocks/options, crypto, B3) has partials and stop moves in the
app; computed slices use `trade_parse_exit(spec, payload, side, slice_qty, entry, null)` (tick check, «Corrigir» where
`correct`, typed where `pnl = typed`, `pnl_required` otherwise, «Custos» per exit where `costs`). Binaries never
(guards: an exit or move on a `binary_option` trade → `not_for_market`).

## 5. Server time, freezing, undo

### 5.1 Guards

`trade_exits_guard` (BEFORE INSERT/UPDATE/DELETE, every role):
- INSERT: `registered_at := now()`, `voided_at := null`, `account_id :=` the trade's; refuses a binary trade or a trade
  without account (`not_for_market`) and an app row on a trade without entry context (`not_app_trade`).
- UPDATE: refused (`append_only`) except (a) `binary_hub.exits = 'void:<id>'` setting `voided_at` once and nothing
  else (`undo_partial`), (b) `binary_hub.exits = 'fix_tz'` moving `exit_time`/`file_exit_at` of a file row with a wall
  clock on an **imported** trade (`import_fix_tz`).
- DELETE: allowed from a cascade (trade or user gone) or for a file row of batch B when `binary_hub.exits =
  'undo:<B>'` (`import_undo`); else `append_only`.
The API cannot set a setting (PostgREST exposes no `set_config`), the same assumption Phase 3 makes for
`binary_hub.deleting` and `binary_hub.save_rules`.

`trade_stop_moves_guard`: strictly append-only (`moved_at := now()`; update refused; delete only from a cascade);
refuses binaries.

Proven: update of a stop move → `append_only`; the old page's DELETE of a trade with exits and moves → cascade, logged
`apagada`; `undo_entry` with a partial and two moves → cascade, logged `desfazer_entrada`.

### 5.2 Freeze summary (adds to `fase3/levantamento/banco.md` §4.3)

| Kind of trade | Never changes | Correctable (server functions only) |
|---|---|---|
| App trade with partials, open | as built + its app exit rows (except `voided_at` once) + its stop moves | — |
| App trade with partials, closed by the app | + `exit_time` (= the final row's) | the file's rows replace the app's as counting exits; sums follow; undo restores |
| Imported grouped trade | its exit rows (except `import_fix_tz` moving wall-clock instants) | an attach adds exits; undo removes them |

### 5.3 Undo rules

| Action | Rule | Effect |
|---|---|---|
| «Desfazer entrada» (`undo_entry`, unchanged code) | live, open, ≤ 15 min after the entry's `registered_at` | trade + exits + moves + marks + context go (cascade); `trade_deletions` row as built; images to the trash |
| «Desfazer parcial» (`undo_partial`, N) | live, open, the last non-undone `parcial` by id, ≤ 15 min after **its** `registered_at` | `voided_at = now()`; kept; never counts; repeatable (walks back) |
| A stop move | none | a new move corrects; the history shows both |
| An exit (`register_exit`) | none (as built) | the file corrects the money |
| An import | `import_undo` | the batch's file exits deleted, its trade columns reverted, the counting exits decide the sums again (§9.7) |

Board copy delta (N): «Desfazer a entrada das {10:12} ({MES · Compra · 3 ct})? A operação, as parciais, os ajustes de
stop e as marcas dela saem do diário. …»; «Desfazer parcial» link under the last partial with «Até {10:21}, 15
minutos depois do registro.»

## 6. The daily limit: each exit when it was realized

### 6.1 `limit_usage` (same signature, `stable`, `search_path ''`)

```sql
d as (select t.id, t.entry_time, t.exit_time, t.pnl, t.commission, t.result from public.trades t join acc …
      where t.account_id in (select id from scope) and t.trading_day = p_day),
t as (
  -- a trade with no counting exit: its single exit, exactly as before
  select coalesce(d.exit_time, d.entry_time) as at, d.entry_time, d.id, 0::bigint as k, d.pnl - coalesce(d.commission, 0) as amount
  from d where d.pnl is not null and d.result is distinct from 'pending'
           and coalesce(d.exit_time, d.entry_time) <= p_until
           and not exists (select 1 from public.trade_exits_v e where e.trade_id = d.id and e.counts)
  union all
  -- a trade with exits: one row per counting exit, an open trade's partials included
  select e.exit_time, d.entry_time, d.id, e.id, e.pnl - coalesce(e.commission, 0)
  from d join public.trade_exits_v e on e.trade_id = d.id and e.counts where e.exit_time <= p_until),
r as (select t.*, sum(t.amount) over (order by t.at, t.entry_time, t.id, t.k rows between unbounded preceding and current row) as running from t)
select jsonb_build_object('trades', count(distinct r.id), 'net_usd', …, 'worst_usd', …, 'hit_at', …) from r
```

- The order key gains `k` (0 for single-exit trades, the exit id otherwise): unchanged order for every existing trade.
- `trades` becomes `count(distinct id)` (a trade with three exits is one trade in «N operações»); equal to `count(*)`
  when every trade is one row.
- The trading day stays the trade's (entry) day: a partial realized after the day turned counts on the day the trade
  opened (decision of Phase 3, «operação aberta de ontem conta no dia em que abriu»).
- It runs as the caller from `gate_at` (invoker); `trade_exits` has `select own` RLS and the API's SELECT grant.

### 6.2 Proof that no existing answer changes

By construction: no trade has a counting exit at migration time (the table is new), so branch 1 is the old query with
one constant column and branch 2 is empty. The conferência proves it on the data anyway (§13.3): before replacing the
function it stores `limit_usage(account, day, soma, usd, at)` for every account, every trading day the account has
trades, `soma` false/true, `usd` null/1/50/the account's own limit, and every instant that matters (each realized
instant of the user's trades that day, now, infinity); after the replacement every answer must be identical, and
`gate_eval` for every account at the stored instant too (the M5d pattern). Prototype: 5,160 answers, 0 changed
(150 ms); the live data (~631 trades, 6 accounts) is the same order of magnitude.

### 6.3 What else sees the change

`gate_at` (and so «Posso operar hoje?», `trade_entry_context.day_pnl_at_entry/worst` of **new** entries,
`trade_limit_room`, `gate_now` after an exit or a partial) now includes realized partials. Stored entry contexts are
frozen and do not change. The app's twin `dayUsage` (`app/lib/domain/gate/usage.ts`) must learn exits (§14).

## 7. Stop moves and the breakeven rule

### 7.1 Stop moves

`move_stop(p_trade, p_move)` (§8.4) on an open live app trade only. «Breakeven» = level `trades.entry_price` now
(`stop_price` key refused with it); `ajuste` = a typed level (`price_dp`, on the tick, > 0). `favor` (string, signed,
up to 8 decimals) is required for a breakeven; with a favour the level must be behind the price it implies
(`(entry + side·favor_Δ − level)·side > 0`, else `bad_stop`: the stop would already have closed the trade); the same
level as the current stop → `same_stop`; 50 moves per trade at most. `prev_stop` = last move or initial stop. The
initial stop never moves (R). Proven: breakeven at +4, breakeven while −1 refused, the same level twice refused, a level
above the price refused, off-tick refused, trailing at 7.914,50 with +6 accepted, `trades.stop_price` unchanged.

Optional (N, if the board wants it): the answer can carry `limit_room` for the remaining risk at the new stop
(open quantity × points to the stop × multiplier vs what is left of the day), a warning only, like the entry's.

### 7.2 The rule in Suas regras (versioned, no spurious versions)

- `AccountRules` (per account, «Vale por conta», like the limit): new optional key `"breakeven": null | {"favor": N}`,
  N a JSON **number** > 0, ≤ 1 000 000, at most 8 decimals, in the instrument's unit of stops (futures and B3 index/
  dollar futures: points; forex: pips; stocks, options, crypto and other prices: a price distance). `MarketRules`
  (market defaults) do not accept it (`unknown_key`): the number depends on what the account trades.
- `rules_check_breakeven(market, p)` (internal): null/absent ok; a market without stops (binary) → `not_for_market`;
  any other shape → `bad_breakeven`.
- `rules_check_account` accepts the key; `rules_check_resolved` accepts 9 keys, or 10 with `breakeven` (an object,
  never null). Replacing a CHECK's function does not recheck stored rows, so the conferência rechecks every
  `account_rule_settings`, `market_rule_defaults` and `account_rule_versions` row.
- `rules_resolve` appends `{"breakeven": {"favor": N::numeric}}` **only** when the account's rules set it.
- `save_rules`, `rules_current`, `gate_eval`, `gate_at`, `rules_config`: code unchanged. `gate_at`'s `"rules"` carries
  the key when present.

Why absent-when-off and not `"breakeven": null` everywhere: `save_rules` versions an account when `rules_current(a) <>
last version` (jsonb equality). A new always-present key would make **every** account's next save (any change, even of
another account's window) create a version nobody chose, forever marking «as Análises contam a partir daqui». With the
key absent, every account resolves to the identical jsonb (proven for every account), stored versions stay valid, and
only the account that sets or clears the rule gets a version (proven: one version, for that account; 8.0 = 8 no
version; a binary account refused; a string or zero refused).

Note for the TS twins: `Resolved` was documented as «every key always present»; it becomes «nine keys, plus
`breakeven` when set». Two versions still compare by plain jsonb equality.

### 7.3 «Sugere sem bloquear» and «confere nas Análises»

- The rule in force for a trade is its version's (`trades.rule_version_id`, the entry's), like every Phase 2 rule.
  `trade_state.breakeven_rule` gives it to the sheet («Sua regra: breakeven com +8 pts»); `move_stop` copies it into
  `rule_favor`. A rule set after the entry does not apply to that trade (null).
- The sheet's suggestions (board): when a partial or the typed favour reaches +N without a breakeven move,
  «Pela sua regra, o stop iria para o breakeven»; a breakeven with favour < N: «antes dos +8 da sua regra» (amber).
  Never a block, never a gate break: `trade_entry_plan` is unchanged (the rule is trade management, not an entry
  condition).
- Facts Phase 6 can check without new data: the rule N (version), the first breakeven move (favour, time, «ao vivo»,
  live or reconstructed), the largest known favour (max over the counting exits' points and every move's favour).
  Proposed verdicts for Phase 6 (not built now): `sem_regra`; `seguiu` (breakeven with favour ≥ N); `cedo` (favour <
  N); `nao_moveu` (no breakeven, known favour ≥ N); `sem_dados` (no breakeven, known favour < N: the price may never have
  reached +N). No MFE exists (no market data), which is why the favour is typed at the move.

## 9. Imports: broker positions with several exits

### 9.1 Positions

In `import_stage`, after `import_checked_rows`: valid rows (not in another account) of a **price** market **with an
exit** are grouped by `(symbol as written, direction, entry instant, entry price)` — the prototype used
`trade_match_key(symbol)`; the exact symbol is safer and equivalent for Top One (a position's rows share it). A binary
row, or a row without exit (Top One `missing_exit`), is always its own position. Ebinex never groups.

### 9.2 What each row is (`path`)

| path | Rule | Then |
|---|---|---|
| `dup` | its ID is a trade's key in the account (`existing_id`) **or** a file exit's ticket (`exit_of`, NEW) | as built: an imported trade **without exits** gets the fields it was missing (the same `insert … on conflict`); a trade with exits gets nothing; an app trade linked earlier with no exits: the as-built patch path |
| `row` | new, alone in its position | exactly as built: one-to-one match to an app trade (same rule, same order), or inserted |
| `group` | new, its position has ≥ 2 new rows and none in the account | matched as a whole, or one imported trade + one file exit per row |
| `attach` | new, and the position's other rows are all in **one** trade of the account | new exits of that trade (§9.5) |

«ID in another account» (`elsewhere`) also checks file exits' tickets. If a position's known rows are in two different
trades (two pre-3c trades), the new rows form their own position (no merge of existing trades).

### 9.3 Matching a position to an app trade

The as-built loop over (row, trade) becomes (position, trade), the position speaking through its first exit's row:
same account, `external_id is null`, same direction and instrument key, app entry between −2/+16 min (−16/+16 for
«Já fechada») of the file's entry, a binary's expiry rule; order: binary expiry = exit, then **same size** (the
position's Σ lots vs `quantity`), then the smaller gap, then the as-built tie-breakers. For a one-row position every key
is the row's own: identical to Phase 3 (proven by suites 20/50/60).

### 9.4 Writing onto an app trade: the row path or the exits path

- **Row path** (as built, unchanged): a one-row position onto an app trade **with no counting exits**
  (`import_link_patch`; closes an open trade at the file's exit ≤ now; `exit_registered_at` stays null).
- **Exits path** (NEW, `import_exits_link(trade, batch, platform, position)`): a position of ≥ 2 rows, or any position
  onto a trade that has app exits, or an attach. It inserts one file exit per row of this file not yet an exit of the
  trade (the trade's own key row too, the first time), then writes on the trade, through `trade_import_links`
  (before/after), the key and entry price (only when they change) and **always** the sums (`quantity, exit_time,
  exit_price, pnl, commission, result, status, pnl_basis`; imported trades also `source_local_exit`), `differs` for the
  money the app had otherwise, `closed` when it closed an open trade, `file_entry_at`, `file_exit_at` (the last row's).
  Writing the sums always (even unchanged) is what lets an earlier batch's undo and this batch's undo compose (found
  and fixed in the prototype: without it, undo oldest-first left `pnl_basis = 'file'`).

**Hours** (decision 2: the file wins on money; hours stay as registered). With F the file rows (ordered by file exit,
line) and A the app's counting exits (ordered; a closed app trade without exit rows counts as one, its exit):

| The app trade | Exit instants of the file rows |
|---|---|
| exit registered by the app, \|F\| = \|A\| | the app's, in order (proven) |
| exit registered by the app, \|F\| ≠ \|A\| | the file's own, kept inside [entry, previous, app exit]; **the last = the app's exit** (frozen) (proven) |
| open | the app's partial hours for the first rows (but never the last: the app never registered the close), the file's own for the rest, never after now; closes at the last (proven) |
| open, and the file's last exit is after now | no exits written: key and entry price only (as built for such a row) |
| imported trade (attach) | the file's own instants (proven) |

The app's own exit rows stay (frozen) and stop counting while file rows exist. Proven (scenario 2): app 3 ct with a
partial then the exit; a file of 2 rows with other prices → the file's money (US$ 98,75, commission 1,86), the app's
hours, `differs = {pnl, exit_price}`, the registered exit hour unchanged, the limit at the app's hours; undo → the trade
and its exits byte-identical to the registration.

### 9.5 Attach: a later file brings more exits of a position already in the account

Example: file A exported mid-session has the first exit (ticket X) → one imported trade (or one row-path link). File
B has X and Y (same open) → X is `dup`, Y is `attach` to that trade; the exits path writes X (from file B) and Y as
file exits of batch B and the sums. Proven for an imported trade (undo B → as A left it) and for an app trade linked by
A through the row path (undo A then B, and B then A → as registered).

### 9.6 Commit answers and batch counts

- One-row files answer exactly as built (proven: suites 20 and 60 compare whole objects). When the file had partial
  exits the answers gain keys (N): preview `trades_new`, `grouped` (rows that are partial exits of another row's trade),
  `attached`; commit `trades`, `grouped`, `attached`. Board copy (N): «{3} linhas novas: {2} operações, {1} saída
  parcial juntada à sua operação.» / «{1} saída a mais de uma operação que já estava.»
- `import_batches` keeps the disjoint line counts of `20261021000001`: `rows_inserted` = lines that went into new trades
  or were attached to an imported trade; `rows_linked` = lines written on app trades (row path: 1 per link, as built;
  exits path: the position's lines); `rows_duplicate` = `dup` lines minus the app completions; `rows_completed` as
  built. Proven: a 2-line position onto an app trade → `rows_linked = 2`, answer `linked = 1`.

### 9.7 Undo

For each link row of the batch (newest first): delete the batch's file exits of that trade (flag `undo:<batch>`),
revert every column still equal to the batch's `after`, reopen a trade the batch closed (as built), give back to
**later** batches' `before` (§9.8), then `trade_exits_apply` (the exits that count again — the app's, or another
batch's — decide the sums). Then delete any remaining file exits of the batch, the batch's link rows, its own trades
(their exits by cascade). Proven in every scenario above, in both orders.

### 9.8 A pre-existing bug fixed on the way (report to the orchestrator)

`import_undo` (`20261020000004:595-603`) patches the `before` of **every other** link of the trade whose value equals
the undone batch's `after`, meant for a *later* batch that captured it. An *earlier* batch whose `before` (the
registered value) happens to equal the undone batch's `after` is rewritten too. Reproduced on the as-built functions
(`proto/asbuilt_undo_order.sql`): register pnl 100; file A says 80 (linked); file B, same ticket, says 100 (the broker
corrected it; completes the app trade); undo B then A → **80**, not the registered 100. Fix in 3c's `import_undo`:
`… and x.linked_at > l.linked_at`. With it the same script ends on 100, and every undo-order scenario passes. Live
impact: none today (needs two batches on one app trade with such a collision; the live project has 2 app trades).

### 9.9 `import_fix_tz`

Moves imported trades as built and, in the same call, their file exits from their own wall clock (flag `fix_tz`; rows
with an explicit offset never move; file rows on app trades never move, as app trades never do). An imported grouped
trade's `source_local_exit` is its last exit's, so `trades.exit_time` and the last exit move together (proven: −5 min
and 0 relative offsets kept after a Brasília fix).

### 9.10 The owner's existing pair

The 2-row Top One position in the live data, if it was imported before 3c, is two trades (two tickets, each a
`trades.external_id`). Re-importing that file: both rows are `dup` with no exits → the as-built completion path → no
change (proven with an invented pair: answer `{"inserted": 0, "duplicate": 2, …}` as before; the rows untouched). They
are never merged automatically (Q4).

### 9.11 Other brokers (3b)

The column import (3b) goes through the same `import_stage`: a broker that writes one row per exit groups the same way;
one that writes one row per position never has two rows with the same open, so nothing changes for it. The mapping must
provide the open instant and open price per row.

## 16. Questions and defaults (each with the recommendation the design follows)

- **Q1 Partial hour cap.** Default: no cap, like «Hora da saída» (as built); alternative: 15 minutes for partials only.
- **Q2 «Desfazer parcial».** Default: yes (last partial, 15 minutes, kept as undone). Alternative: no undo (the file
  corrects money).
- **Q3 Marks after a partial.** Default: still «antes da saída» until the final exit (the result is not known until the
  trade closes; the as-built rule uses the final exit). Alternative: «depois do resultado» from the first partial.
- **Q4 The existing 2-row pair.** Default: stays two trades (nothing that exists changes). Alternative: a one-off,
  undoable «Juntar como parciais» later.
- **Q5 Breakeven rule scope.** Default: per account. Alternative: a market default with per-account override (would add
  the key to MarketRules; still no spurious versions with the absent-when-off rule).
- **Q6 A mid-session export.** A file exported while a position is still open shows only its closed rows; an open app
  trade is closed by the file at its last row (Phase 3 rule kept). Default: keep (undo the import if it happens).
